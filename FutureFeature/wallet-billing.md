# Wallet / Billing Tab (Future Feature)

## What
A "Wallet" tab in the dashboard where each client account can prepay balance (via Razorpay) and gets auto-deducted per message/broadcast sent. Modeled after existing tools like AiSensy/WATI/Interakt.

## Why
Meta doesn't offer a prepaid-balance API for WhatsApp Cloud API (messaging billing is postpaid, charged to whichever card is on the WABA) and doesn't let third parties top up a client's Meta account. So "add balance" has to be our own in-app wallet, not a Meta feature.

## Model (current plan: Model A)
- Each client keeps their own Meta WABA/number connected (as today, via `whatsapp_config`).
- Short term (small client base, e.g. ~10 clients): put our own card on all client WABAs/Business Manager, Meta bills us in one combined invoice, we collect the equivalent + margin from clients via their in-app wallet.
- Risk: cashflow exposure if a client's wallet runs dry before Meta charges us — deduction must be real-time and block sending at zero balance, never let usage go negative.
- Long term (once scale grows past small client base): become a Meta Tech Provider / Business Solution Provider (BSP) — client WABAs live under our Business Manager with proper per-client credit lines, removing the shared-card risk. Requires formal Meta approval/business verification.

## Core pieces to build (when we get to it)
1. **DB**: `accounts.wallet_balance_cents` + `free_credits_remaining` + `wallet_transactions` table (credit/debit ledger), account-scoped like every other table (see `whatsapp_config` pattern for account_id + RLS).
2. **Top-up flow**: Razorpay order-create → Checkout widget → server-side signature verification (never trust client-reported success) → credit wallet.
3. **Deduction flow**: on every successful send in `src/lib/whatsapp/meta-api.ts` / broadcast send path, atomically deduct cost (guarded SQL update, e.g. `UPDATE ... SET balance = balance - cost WHERE balance >= cost`) — free credits consumed before paid balance. Block/skip remaining sends if balance hits 0 mid-broadcast.
4. **UI**: `/billing` tab — balance, message rate, "Add money" (presets + custom amount), transaction history table. Nav entry in `sidebar.tsx`, i18n under `Billing` namespace.
5. **Ads spend (optional, read-only)**: Facebook Marketing API exposes `amount_spent`/`balance`/`spend_cap` on the Ad Account object (`GET /act_{ad_account_id}`) for display only — no top-up via API, client still funds Ads directly in Meta Ads Manager.

## Explicitly not possible via Meta API
- No prepaid balance/wallet concept for WhatsApp messaging on Meta's side.
- No way to inject money into a client's Meta account (WABA or Ad Account) programmatically — top-ups there always happen on Meta's own billing pages.
